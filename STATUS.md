## Current outcome

The ecosystem is in an execution-phase simplification: Integrity remains the trust substrate;
Shield and Cortex remain independently operable products; the console and lab are separate
repository boundaries. Local operation must not depend on an oracle, public chain, vendor, or
hosted service being available.

## Product boundaries

- **Integrity core:** SDK, contracts, Oracle/AIS, BCC/OPA, CLI, and the trust-bearing artifact
  contracts. AIS authority remains in Oracle/scoring-core; other products report operational and
  provenance metrics rather than recomputing AIS.
- **Shield:** local endpoint enforcement and signed evidence. It must continue enforcing during
  chain, Oracle, or hosted-service outages.
- **Cortex:** local governed memory, content, provenance, retention, retrieval, and evidence.
  It must continue storing and retrieving while anchoring is unavailable.
- **Integrity console:** operator UI and user API boundary after the A1 split.
- **Integrity lab:** frozen mirror for removed, historical, or deferred code; it is not a runtime
  dependency of the trust substrate.

## Verified foundations

- JCS/RFC 8785 is the SDK canonicalization authority for newly migrated hashed or signed data;
  legacy formats remain explicitly versioned where migration is not complete.
- Signed packs cover the files they evaluate, and pack loading verifies the trusted signature
  before enforcement uses the pack.
- Decision and receipt contracts define fail-closed behavior for missing, malformed, unknown, or
  incompatible decisions; no-match behavior is pack-declared.
- Agent private keys are kept outside harness roots; the root DID file is public identity
  material. See `integrity_sdk/did.py` and the execution-plan identity decision.
- Documentation TOCs pass `python3 scripts/wiki_toc.py --check` for all 35 canonical wiki pages.
